### What breaks offline

**Everything.** The app is a standard Next.js SSR/SSG application with no offline capabilities:
- Cannot load any page without network (no service worker cache)
- Cannot authenticate (Clerk requires network)
- Cannot record audio (not implemented at all)
- Cannot save data (no local storage)
- Cannot sync (no sync queue)

**Verdict:**
- **F-18 CONFIRMED** — "Offline-Ready" badge is false. The app has zero offline capability.
- **F-19 CONFIRMED** — Recording does not exist, so audio loss is a given.
- **F-20 CONFIRMED** — AI synthesis does not exist; no queue.
- **F-21 CONFIRMED** — No sync mechanism exists.

## 7. Summary

### Overall Assessment

**DaktariScribe is a Next.js UI shell with Clerk authentication and extensive legal/marketing copy that claims features, security controls, and compliance certifications that do not exist in the codebase.** The core product loop (capture → transcribe → synthesise → review → export) is entirely unbuilt. Every dashboard feature is a static visual prototype.

### Risk Summary

- **S1 (Critical):** 5 findings confirmed — false legal claims, missing review gate, no offline capability, vulnerable dependencies
- **S2 (High):** 17 findings confirmed — auth gaps, no data isolation, no consent, no structured data
- **S3 (Medium):** 14 findings confirmed — UI/UX issues, naming inconsistency, accessibility gaps
- **S4 (Low):** 3 findings confirmed — polish items

### Immediate Actions Required

1. **Update `next` to 16.4.3+** — critical security vulnerabilities (TASK before Phase 1)
2. **Run `npm audit fix`** — resolve all non-breaking dependency vulnerabilities
3. **Rewrite legal pages** — remove all unimplemented claims (TASK-1.4)
4. **Remove or change "Offline-Ready" badge** — currently false (TASK-3.7)
5. **Remove or change "Clinician-Vetted" badge** — no evidence (TASK-4.2)
6. **Add `.env.example`** — document required variables without values
