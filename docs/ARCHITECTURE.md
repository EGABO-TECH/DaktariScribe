## 2. Routing (App Router)

All routes use the Next.js App Router under `app/`.

| Route | Type | Auth Required | Description |
|---|---|---|---|
| `/` | Landing + Login | No | Hero section + sign-in card (combined page) |
| `/register` | Registration | No | Multi-field sign-up form with email verification |
| `/forgot-password` | Password Reset | No | Email → code → new password flow |
| `/sso-callback` | OAuth Callback | No | Clerk `AuthenticateWithRedirectCallback` |
| `/field-entry` | Dashboard | **Yes** | Voice dictation workspace (static UI prototype) |
| `/saved-records` | Dashboard | **Yes** | Encounter records table (hardcoded mock data) |
| `/reports` | Dashboard | **Yes** | Report cards with mock data + `window.print()` PDF |
| `/legal/privacy` | Legal | No | Privacy Policy |
| `/legal/terms` | Legal | No | Terms of Service |
| `/legal/compliance` | Legal | No | Compliance Framework |
| `/legal/security` | Legal | No | Security Documentation |

### Route Groups

- `(dashboard)` — groups `field-entry`, `saved-records`, `reports` under a shared layout with Sidebar + Header + BottomNav.

## 3. Authentication Provider

| Aspect | Detail |
|---|---|
| **Provider** | [Clerk](https://clerk.com) (`@clerk/nextjs` v7.8.3) |
| **Strategies** | Email/password, Google OAuth (via `oauth_google`) |
| **Middleware** | `clerkMiddleware` + `createRouteMatcher` in `middleware.ts` |
| **Protected routes** | `/field-entry(.*)`, `/saved-records(.*)`, `/reports(.*)` |
| **Email verification** | Yes — 6-digit email code after registration |
| **Password reset** | Email code → new password (Clerk `reset_password_email_code`) |
| **MFA** | Not configured in code (Clerk supports it, but not enabled) |
| **Session management** | Handled entirely by Clerk (cookie-based) |
| **Google SSO** | Available on Login page only (NOT on Register page) |
| **Post-auth redirect** | `/field-entry` |

## 4. Database / Storage

**None implemented.** There is no database, no Supabase, no Firebase, no Prisma, no Drizzle. All data on the dashboard screens is **hardcoded mock data** (see `reports/page.tsx` `mockReports` array and `saved-records/page.tsx` inline array).

No API routes exist (`app/api/` directory is absent).

## 5. AI Provider SDKs

**None implemented in the codebase.** The `.env.local` references `AI_MODEL_PROVIDER=openai` and `AI_MODEL_NAME=gpt-4o`, but:
- No `openai` package in `package.json`
- No API routes or server-side code that calls any AI model
- No speech-to-text integration
- No transcription pipeline

The AI synthesis pipeline described in marketing copy is **not built**.

## 6. PDF Library

**None.** The `ReportCard.tsx` "Download as PDF" button calls `window.print()` — a browser print dialog, not real PDF generation. No `jspdf`, `@react-pdf/renderer`, `puppeteer`, or any PDF library is installed.

## 7. Speech-to-Text Path

**Not implemented.** The field-entry page shows a static UI prototype with animated waveform bars and Start/Pause/Stop buttons, but:
- No `MediaRecorder` usage
- No `navigator.mediaDevices.getUserMedia` calls
- No Web Speech API usage
- No integration with any STT service (Whisper, Deepgram, Google Cloud, etc.)
- Buttons have no `onClick` handlers

The entire dictation interface is a **visual prototype only**.

## 8. State Management

- **React `useState`** — used in login, register, forgot-password forms
- **No global state** — no Redux, Zustand, Jotai, Context providers (beyond Clerk)
- **No data fetching** — no SWR, React Query, or fetch calls beyond Clerk auth

## 9. PWA / Service Worker Status

**Not implemented.**
- No `manifest.json` or `manifest.webmanifest` in `/public`
- No service worker registration
- No Workbox or Serwist configuration
- No IndexedDB usage
- No offline capability whatsoever

The "Offline-Ready" badge on the landing page is **false**.
