# DaktariScribe — Encounter Lifecycle (Workflow)

> Generated by Phase 0 audit. Last updated: 29 October 2026.

---

## Current State

The encounter lifecycle is **almost entirely unimplemented**. What follows documents both (a) the **intended** lifecycle from marketing/legal copy, and (b) the **actual** implementation status of each step.

## Intended Encounter Lifecycle

```mermaid
sequenceDiagram
    participant U as Clinician
    participant App as DaktariScribe App
    participant Auth as Clerk Auth
    participant DB as Database
    participant STT as Speech-to-Text
    participant AI as AI Pipeline
    participant PDF as PDF Engine

    U->>App: Open app
    App->>Auth: Check session
    alt Not authenticated
        Auth-->>App: Redirect to /
        U->>App: Sign in (email/password or Google)
        App->>Auth: Authenticate
        Auth-->>App: Session created
        App->>U: Redirect to /field-entry
    else Authenticated
        Auth-->>App: Valid session
        App->>U: Show dashboard
    end

    U->>App: Create encounter (title, camp location)
    Note over App,DB: ❌ NOT IMPLEMENTED — No encounter creation

    alt Voice capture
        U->>App: Start recording
        App->>App: MediaRecorder captures audio
        Note over App: ❌ NOT IMPLEMENTED — No MediaRecorder
        App->>App: Store audio chunks locally
        Note over App: ❌ NOT IMPLEMENTED — No local storage
        U->>App: Stop recording
        App->>STT: Send audio for transcription
        Note over App,STT: ❌ NOT IMPLEMENTED — No STT integration
        STT-->>App: Transcript text
    else Text capture
        U->>App: Type encounter notes
        Note over App: ❌ NOT IMPLEMENTED — No text input handling
    end

    App->>DB: Save transcript/notes
    Note over App,DB: ❌ NOT IMPLEMENTED — No database

    U->>App: Request AI synthesis
    App->>AI: Send transcript to multi-model pipeline
    Note over App,AI: ❌ NOT IMPLEMENTED — No AI pipeline
    AI-->>App: Structured clinical note (SOAP)

    U->>App: Review/edit AI draft
    Note over App: ❌ NOT IMPLEMENTED — No review screen

    U->>App: Mark as reviewed
    Note over App: ❌ NOT IMPLEMENTED — No review gate

    U->>App: Export PDF
    App->>PDF: Generate clinician-ready PDF
    Note over App,PDF: ❌ PARTIAL — window.print() only
    PDF-->>U: Download/share PDF
```

## Actual Implementation Status

### ✅ What Works

1. **Authentication flow:**
   - Sign in with email/password → Clerk creates session → redirect to `/field-entry`
   - Sign in with Google OAuth → redirect to `/sso-callback` → redirect to `/field-entry`
   - Register with email → 6-digit email verification → session created → redirect to `/field-entry`
   - Password reset via email code → new password → auto-sign-in
   - Protected route middleware blocks unauthenticated access to dashboard routes

2. **Dashboard shell:**
   - Sidebar navigation (desktop), bottom nav (mobile)
   - Header with user greeting and Clerk `UserButton`
   - Visual layout of three dashboard pages

3. **Static UI prototypes:**
   - Field Entry: animated waveform, Start/Pause/Stop buttons (non-functional)
   - Saved Records: table with hardcoded rows, filter UI (non-functional)
   - Reports: cards with mock data, "Download as PDF" triggers `window.print()`

## Summary

**DaktariScribe is a UI shell with authentication.** The core product loop (capture → transcribe → synthesise → review → export) is entirely unbuilt. All dashboard functionality is mock/static HTML with no interactivity, no data persistence, and no AI integration.
